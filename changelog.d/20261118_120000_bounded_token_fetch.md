### Fixed

- A span export no longer waits for a Keycloak token longer than the exporter's own timeout (`OTEL_EXPORTER_OTLP_TRACES_TIMEOUT`, else `OTEL_EXPORTER_OTLP_TIMEOUT`, else 10 s). The token was fetched while the request was prepared, before that timeout applied, so a cold or expired token with a slow Keycloak held a flush for the 10 s `TOKEN_REQUEST_TIMEOUT_SECONDS` per batch and project. A wait that passes the budget fails that export, which the exporter logs and drops. Only the wait for the token is bounded, not the export: `requests` fixes the request's timeout before the token is fetched, so one attempt can still take about twice the timeout (four times after a 401). `KeycloakTokens` now runs one token request at a time on a daemon thread. A bounded caller (`token(timeout=...)`, `RequestsBearerAuth(timeout_seconds=...)`) waits at most that long in wall-clock time, then fails at once while that request still runs and for `FAILED_FETCH_BACKOFF_SECONDS` (5 s) after one fails, so a flush against a hung Keycloak waits about one timeout in total. The Opik SDK's auth and the memory service wait for the request as before, with the 10 s HTTP timeout.
