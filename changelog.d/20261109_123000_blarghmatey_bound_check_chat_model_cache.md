### Security

- `check_chat_model`, the embedding catalog check, and the models and embedders `complete` and `embed` (and their `_sync` forms) run on are no longer kept for every use case for the life of the process. An application that builds a use case from a request's model id kept one of each, provider clients included, for every distinct id a caller sent. A use case whose models the catalog all lists stays cached, up to 1,024 of them (`CHECKED_USE_CASES_MAX`). A use case naming any model the catalog does not list is kept only among the 64 most recently used (`UNCATALOGED_USE_CASES_MAX`), so a caller cycling ids can't evict the application's own use cases. Such a use case builds new clients, and its unlisted-model warning is logged again, once it falls out of those 64.
- `UseCase` raises `ValueError` when `model` or any of `fallback_models` is longer than 512 characters (`ol_llm.policy.MODEL_ID_MAX_CHARS`), so an application that builds a use case from a request's model id refuses an oversized id before it reaches a cache, a log line or a provider. The error gives the id's length, not the id.
- The catalog's unlisted-model and deprecation warnings write the model id with `repr`, so an id carrying a newline can't start a forged log line.
