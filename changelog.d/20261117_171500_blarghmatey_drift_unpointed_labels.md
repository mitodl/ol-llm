### Changed

- `ol-llm-prompts check --environment` also reports a prompt in the app's namespace that carries the label while no pointer names it (`<name>: production is on v2, and no pointer names it`) and exits 1 for it, as for a drifted pointer. Only the promotion job is meant to move `production`, so such a label was moved some other way. The scheduled drift report runs ol-llm at the commit the app's workflow pins (`uses: mitodl/ol-llm/.github/workflows/prompt-promotion.yml@<commit>`), so this applies once that ref is bumped; the pull request that bumps it still passes, since pull requests run `check` without `--environment`, and the next scheduled report fails if the app's Opik project has labeled prompts its pointer file does not name. Add pointers (and their exports) for those prompts in or before that pull request. Do not remove the label instead while the app still reads it, since a fetch by that label then fails. (#85)
- `PromptRegistry` has a new abstract method, `prompt_names(app=...)`, which lists the prompts in an app's namespace. A custom registry, whether registered through the `ol_llm.prompt_registries` entry points or passed to `configure_prompt_registry`, has to implement it. (#85)
